The capture-blend regression specs exercise all 18 modes against an independent W3C oracle, including opaque and translucent destination coverage, Sprite, Mesh, custom SpriteMaterial, opaque Text glyphs, particles, nested captures, cached replay and a provably opaque target. The source alpha stays 0.7 for the numeric Sprite/Mesh/particle cases. Readback stores premultiplied linear RGBA8 bytes; tolerance is 5. A throwing capture also checks that subsequent draws retain their own blend state.

Run the named specs with `node node_modules/vitest/vitest.mjs run --project browser-webgl-chromium test/rendering/browser/webgl2-capture-blend.test.ts` and `--project browser-webgpu test/rendering/browser/webgpu-capture-blend.test.ts`. The GL2 file also runs under `--project browser-webgl-firefox`.

`comparison.json` records the baseline, unchanged PR866 and repair runtime file hashes, all numeric samples at 1280x720 and 512x288, source hashes and same-frame public renderTo reproduction. The before/after PNGs show the same fixed Luminosity scene on a transparent background. The repair reaches maximum error 1 on both Chromium backends; baseline and PR866 fail identically.

`emitter-parity.json` is a separate unresolved visual comparison. Math.random is seeded with 0x316645, the emitter is reset, advanced for 120 fixed steps of 1/60 second, then paused with 120 CPU particles. At 1280 pixels, the presented canvas crop is byte-identical before/after separately on each backend, but GL2 versus GPU differs at 2521 pixels above tolerance 5 (maximum difference 235). GL2 remains mosaic-like and GPU remains soft. The 512-pixel GPU screenshots also include small browser resampling differences; this evidence does not accept emitter parity.
