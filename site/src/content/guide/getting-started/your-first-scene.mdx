# Your first scene

Start with the `minimal` project from [Setup](/ExoJS/en/guide/getting-started/setup/). It draws a rotating square without downloading textures or audio. A visible object gives you a working baseline before you need to reason about loading and network failures.

## Define the scene

The maintained starter's scene contains one graphics object:

`Graphics` stores the rectangle. The rectangle is centered around the object's local origin, then placed at `(400, 300)` in the starter's 800 by 600 canvas. `addChild` attaches it to the scene's root container.

The constructor only creates local objects. Application-bound services such as `this.app`, `this.loader`, and `this.inputs` are not available there. Use `init()` for setup that needs those services; use the awaitable `load()` hook for asynchronous prerequisites. The [lifecycle chapter](/ExoJS/en/guide/runtime/scenes-and-lifecycle/) explains their order and cleanup.

## Update state, then draw it

`update(delta)` receives elapsed time in **seconds**. The starter rotates the square by `90 * delta`, giving a rate of 90 degrees per second. Changing `90` changes the speed; omitting `delta` makes the motion depend on the number of frames rendered.

`draw(context)` chooses what to render. `context.render(this.root)` draws the scene hierarchy. Adding an object to `root` does not by itself make the scene draw it: the explicit draw call is required. Avoid creating objects or starting asset requests in `draw`; it should use state that already exists.

The application clears its output each frame by default. Persistent-frame effects are a separate rendering workflow, not something this scene needs.

## Register and start the scene

The starter's entry point creates the application after defining or importing the scene:

`scenes` registers scene **classes**, not constructed scene instances. `app.start(MainScene)` lets the director construct and activate the scene, then starts the runtime. Await startup so a loading or activation failure is visible to the caller.

`canvas.mount: 'body'` attaches the canvas to the page. An unmounted canvas can still receive rendering work while the page appears empty. In an existing layout, mount it into the element that owns your interactive surface instead.

## Make three small changes

Change the rotation rate, the rectangle size, and the clear color. Each edit should affect one visible property. Then move the object by changing its position. This is the basic loop of an ExoJS scene: create state, change it during updates, and render it explicitly.

The [Hello World playground example](/ExoJS/en/playground/?example=getting-started/hello-world.js) extends the idea with a texture-backed sprite. Its tap control pauses the rotation and changes the tint. Loading is deliberately not required for this first tutorial; [Loading and resources](/ExoJS/en/guide/assets/loading-and-resources/) teaches when to await an asset and when a placeholder is appropriate.
