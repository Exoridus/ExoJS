# Cinematics

A cinematic (or cutscene) is a choreographed sequence where the camera moves, dialogue appears, characters animate, music swells, and the player's input is temporarily suspended, all driven by timing. ExoJS provides tweens and `TweenSequencer` for animation timing, `View` for camera movement, scene-owned audio for music, and `app.scenes.change(...)` for transitioning between game states. This recipe coordinates a short sequence with independent tweens and delays.

## Approach

A cinematic is a scene. Tweens drive its camera pan, title reveal, character entrance, and music fade. Create them through `this.tweens` and play music through `this.audio` so they stop when the scene ends. Keep references to the sequence's own tweens so skip can stop them without interrupting animation elsewhere in the application. `CinematicScene` below implements the visuals; `CutsceneFlowScene` extends it with skip input and a return to gameplay.

The key technique: **tween chains and delays**. Each tween starts at a specific time offset. Together they form a timeline:

## The timeline

The sequence above runs as follows:

| Time | Event |
|------|-------|
| 0.0s | Shutter bars start opening. Camera begins panning. Music starts fading in. |
| 1.1s | Boss begins scaling up from 0.4x to 2.1x. |
| 1.6s | Title text begins revealing character-by-character. |
| 2.0s | Camera pan completes. Music reaches its target volume. |
| 2.6s | The full title is visible. |
| 2.9s | Boss reaches its final scale. |
| 3.5s | The flow scene starts closing the shutter bars. |
| 4.1s | The bars are closed; the return to gameplay begins. |

Each tween operates independently — they don't need to know about each other. The `delay()` method offsets the start time. The `.onUpdate()` callback on the title tween drives the character reveal, mirroring the typewriter pattern from [UI patterns](/ExoJS/en/guide/recipes/ui-patterns/).

`scenes.change` is asynchronous — the incoming scene's `load()` has to run before it can activate — and the `void` says the caller is not waiting for it. Switching from an input handler or a tween callback, as here, is exactly that case: there is nothing to hand the promise to. Await it instead when the code around the switch depends on the new scene being live, and catch it if a failed switch needs to reach the player.

Because the cinematic is now the only active scene, the game scene neither renders nor updates for the duration. When the cinematic ends, switch back:

## Skip support

Press Space, Enter, or gamepad Start to stop the sequence, snap its visible state, and return to gameplay with a fade. The scene-owned input binding is removed automatically when the scene ends:

<Callout type="hint" title="Stop only the sequence you own">
Call `stop()` on the stored tween references, then explicitly assign the camera, scale, title, bars, and volume you want to show. Stopping a tween does not fast-forward it or run its completion callback. Avoid `app.tweens.clear()`: it also stops unrelated application and scene tweens.
</Callout>

## When not to build a cinematic system

For a single boss intro, one scene with delayed tweens is sufficient. For sequential beats, use `this.tweens.createSequencer()` to obtain a scene-owned `TweenSequencer`: `then(tween)` adds a stage, `then([a, b])` runs tweens together, and `wait(seconds)` inserts a pause. Build a separate cutscene authoring layer only when your content needs more than these timing primitives.
